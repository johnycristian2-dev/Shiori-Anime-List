# App Shiori (.NET MAUI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App de celular do Shiori em .NET MAUI: 6 telas nativas (Login, Início, Busca, Detalhe, Minha lista, Perfil) + todo o resto do site num WebView já logado.

**Architecture:** Lógica sem tela numa biblioteca `Shiori.Core` (net10.0, testável com xUnit): autenticação, lista e AniList, todos com `HttpClient` puro (sem SDK do Supabase, para o dono ver e explicar cada requisição). O app `ShioriApp` (MAUI, MVVM com CommunityToolkit.Mvvm, Shell com abas) usa o Core. A parte web é o site publicado num `WebView`, recebendo a sessão do app pelo `localStorage`.

**Tech Stack:** .NET 10 SDK 10.0.401, MAUI (android, windows, ios), CommunityToolkit.Mvvm, System.Text.Json (JsonNode), xUnit.

**Spec:** `docs/superpowers/specs/2026-11-24-app-maui-design.md`

## Review Focus

- **Token renovado pelo site invalida o do app** (o Supabase troca o refresh token a cada renovação): ao sair da WebPage, o app relê a sessão do `localStorage` e fica com a mais nova (`expires_at` maior). Teste em Task 2 (`PicksNewestSession`).
- **Sessão vencida e renovação recusada**: volta para o Login com aviso, sem travar. Teste em Task 2 (`RefreshFailure_ClearsSession`).
- **Usuário novo sem linha em `user_data`**: cria o doc com `entries`, `deleted`, `lists`, `skipped` vazios. Teste em Task 3 (`MissingDoc_CreatesEmpty`).
- **Anime removido antes e adicionado de novo no app**: `updatedAt` novo maior que o `deleted[id]`, e a lápide é apagada, para o site não esconder. Teste em Task 3 (`ReAdd_AfterDelete_ClearsTombstone`).
- **Sem internet / AniList fora**: mensagem "Sem conexão. Toque para tentar de novo." na tela, nunca exceção sem tratamento. Teste em Task 4 (`HttpError_ThrowsShioriException`) + estado de erro nos ViewModels.
